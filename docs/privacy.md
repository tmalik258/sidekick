# Privacy

Duskie runs on your PC and keeps what it sees there.

- **Events and history** are stored in a local SQLite database under `%APPDATA%\app.sidekick.desktop\` (or `app.sidekick.desktop.dev` when you run `pnpm dev`). You can pause all sensors from the tray or Ask mode, and switch each one off in Settings > Privacy and data.- **Ignored apps and sites** (Settings > Privacy and data): nothing from them is stored, indexed or shown to skills. Password managers are on the list from the start.
- **Morning setup** (Settings > Skills): the first time you open each app, and each site in your active tab (with the browser extension, domain only, never the page), during the first hour of a day. Kept for 60 days on this PC to suggest your usual start. Turn it Off, take one app out with a click, or press Start over any time.
- **Work log**: Save to work log appends to Documents\Duskie\worklog.md, only when you press it.
- **Clipboard secrets** (keys, tokens, passwords) are detected and never stored, indexed or sent to AI.
- **Secrets in chats and agent work** (API keys, tokens, private keys, passwords) are shown as dots in saved chats, agent transcripts, command output and the change review.
- **Copy diagnostics** (Settings > Home > About) copies the version, Windows version, which models answer, recent timings and the end of the log, with secrets and your user name taken out. Nothing is sent; you paste it where you choose.
- **Crash reports** are off until you turn on Offer to report crashes. After a crash Duskie then shows the error and opens a GitHub issue you can read and edit before sending. Nothing is sent on its own.
- **Browser password stores** are never read or written. Cookies are never read.
- **AI** only sees what you send it: your question, plus the window, clipboard, page or screenshot you choose to attach. Claude Code runs in an empty folder and Duskie never reads its credential files.
- **Voice** is on by default and can be turned off in Settings > AI. Speech recognition and the Supertonic voice run on this PC; audio is never saved or sent. Only the words you say go to your AI, like a typed question. **Live answers** (off by default) start the answer when you pause; a change still waits for the final words and a tap on screen, and voice alone never confirms anything that deletes or closes.
- **Text from mail, web pages, files and the screen** is treated as untrusted. Once it is read in a turn, Duskie will not make a change unless your own words asked for one.
- **Search by meaning** uses an embedding model on your own local server; text never leaves the PC.
- **Localhost endpoints** (Claude Code hooks, browser extension, MCP) listen on 127.0.0.1 only, refuse web pages, and the browser and MCP ones require a token.
- **Updates**: once a day Duskie asks GitHub for the latest release number. You can turn this off.
- **Backups** (Settings > Home > Backup) hold your settings, own skills and action history; keys and sign-ins are left out.
- **Composio** (off until you connect it): calendar reminders, the morning brief and Fathom follow-ups read your apps through Composio, and in Ask mode the local model can use it as tools. Requests (for example a calendar or Jira search) go to Composio and on to that app. The local model can only read; changes go through Claude Code, which asks first. Duskie connects to Composio Connect (connect.composio.dev), the same service Claude uses, so the apps already connected in your Composio account work without connecting them again. The sign-in (or a consumer key you paste) is kept in Windows Credential Manager, not in the settings file, and never in backups. Questions marked "This PC only" never use Composio.
- **Claude Code settings** are only changed when you press Add for me or Always in this project, and `~/.claude/settings.json` is backed up first.
- **Continue in Claude Code** writes the conversation to a file in Duskie's AI folder and opens Claude Code with it, only when you press the button.
- **Gmail** (off until you press Connect Gmail in Settings > Home > Notifications): Duskie signs in with Google in your browser and asks only for read access to mail. For each new unread message it reads the sender and the headers, plus a short piece of the text to see whether it is a question or mentions a deadline, and keeps only yes or no answers. The subject, text and snippet are never saved, logged or sent anywhere. Mail you already read on another device is skipped. The sign-in is kept in Windows Credential Manager, never in settings or backups. Disconnect revokes it at Google and deletes it from the PC.
- **What Duskie learns about notifications** (Settings > Home > Notifications) is a small score per sender or app, taken from what you act on and what you ask for less of. Dismissing teaches nothing. It fades over about a month, can be reset per row, per group or all at once, and holds no message text.
- **Gmail through Composio**: if you have not connected Gmail here but your Composio account has Gmail connected, Duskie checks it through Composio every couple of minutes instead. It asks for unread inbox mail from the last day, keeps the same yes or no answers as above and nothing else, and only raises mail that arrives after it starts. Connecting Gmail directly takes over from it.

- **Other mail (IMAP)**: under Advanced you can connect any provider with an app password. Duskie connects over TLS with certificate checks (no plaintext fallback), reads only the headers of new unread mail, and keeps the password in Windows Credential Manager. Disconnect deletes it.

- **Apps over MCP** (Settings > Connections): a server on this PC starts only after you confirm its exact command, and its secrets are kept in Windows Credential Manager. Online servers sign in through your browser; the token is kept the same way. Tools that change things stay off until you allow them one by one.
- **Skills library** (Settings > Skills > Library): Duskie reads the skill folders of Claude Code (`~/.claude/skills`, `~/.claude/plugins`) and Codex (`~/.codex/skills`) to list what you have. It copies only the skills you add, and never runs anything in them. Adding from a link downloads that folder from GitHub at one commit. The local model reads a skill only when it is switched on for it.
- **Editor and terminal**: the editor reads and writes files only inside the project you opened. The terminal is your own shell in that folder; nothing you type is stored.
